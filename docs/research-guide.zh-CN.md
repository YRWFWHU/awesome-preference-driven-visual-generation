# 用户偏好驱动视觉生成：研究与阅读指南

本指南以文生图为主。这里的“偏好驱动个性化”是本仓库的操作性定义：根据某个用户的历史、反馈或偏好描述，推断或使用其偏好，在满足当前任务的同时生成更符合该用户的结果。它不代表学界已经形成统一术语。

推荐与信息检索社区的补充路线见 [WWW / SIGIR / KDD 阅读地图](ir-conference-guide.zh-CN.md)，涵盖 Pigeon、DiFashion 系列、DPPMG、PerFusion 以及广告生成中的群体/总体偏好边界。

**阅读约定：**“论文报告”指作者在其数据和协议下的观察，本仓库没有独立复现；“整理判断”指维护者根据已核验资料做的分类与方法比较；“待验证问题”是开放的研究提问，不是“尚无人研究”的新颖性声明。逐条来源、核验日期和未知字段见 [JSON](../data/resources.json)。

## 先划清边界

个性化不能仅凭论文标题或 preference loss 判断。要问：用户是谁、信号来自哪里、生成如何依赖这个用户、评价者是否就是这个用户？喜欢图、负反馈、评分、成对选择、自然语言说明或隐式历史都可以构成信号，不要求一定有负反馈、奖励模型、RL 或 DPO。

指定一张风格图作为复现目标，与从历史图推断审美倾向不同，但两者存在交集。风格当然可以是偏好的一部分。[StyleDrop](https://arxiv.org/abs/2306.00983) 研究指定风格的适配，并使用迭代反馈，本仓库将其列为边界基线。[DreamBooth](https://arxiv.org/abs/2208.12242) 主要研究主体保真；保留某个人或物体的身份，不等于推断用户对其他内容的偏好。这些是基于论文任务的整理判断。

[Pick-a-Pic / PickScore](https://arxiv.org/abs/2305.01569) 也有两种不同角色：可保留用户标识的数据支持个体研究，而没有用户条件的评分函数属于总体偏好评价。不要把“数据由真人提供”直接等同于“模型为个人服务”。

## 用户反馈 → 偏好表示/模型 → 生成控制 → 评价

| 环节 | 需要记录的问题 | 已核验阅读入口 |
| --- | --- | --- |
| 用户反馈 | 历史是保存、点击、评分还是明确表达的原因？有没有负例？ | [Tailored Visions](https://arxiv.org/abs/2310.08129)：历史 prompt；[ViPer](https://arxiv.org/abs/2407.17365)：对喜欢/不喜欢图像的自然语言评论 |
| 偏好表示/模型 | 用文本属性、用户向量，还是条件化评分？是否与当前 prompt 交互？ | [PPD](https://arxiv.org/abs/2501.06655)：比较样本到用户表示；[Premier](https://arxiv.org/abs/2603.20725)：用户向量与 prompt 融合 |
| 生成控制 | 改 prompt、训练适配器、选择候选还是改变采样？ | [DrUM](https://arxiv.org/abs/2508.03481)：条件空间适配；[PAMELA](https://arxiv.org/abs/2604.07427)：个性化评分驱动 prompt 搜索 |
| 评价 | 衡量相似、评分预测，还是目标用户实际选择？ | [PIPBench](https://arxiv.org/abs/2607.06440)：真实与合成档案评测；[PIGReward](https://arxiv.org/abs/2511.19458)：评分与生成实验分开阅读 |

这些路线可以组合。比如用户表示可同时用于 prompt 改写和采样引导；有固定用户向量也不意味着偏好效果与 prompt 无关。尤其不能假定历史喜欢图的共同特征就是喜欢它们的原因：重复主体、生成器的固有画风或图片曝光机制都可能造成内容混杂。

## 训练与新用户适配设定

阅读时分开记录离线共享训练、新用户接入和每次生成的成本。“无需微调”可能只指冻结生成器，而偏好提取器或共享适配器已经训练过。

- **历史驱动的直接推断：**[Tailored Visions](https://arxiv.org/abs/2310.08129) 从历史检索并改写；[ViPer](https://arxiv.org/abs/2407.17365) 将评论转成属性，再控制生成。后者的偏好提取器训练包含模拟用户，不能把整套系统称为完全未经训练。
- **共享模型吸收多用户信息：**[PPD](https://arxiv.org/abs/2501.06655) 从少量比较样本获得新用户条件，区分未见用户与保留 caption 的测试；[PrefGen（多模态）](https://arxiv.org/abs/2512.06020) 学习历史表示并与生成模型对齐。要区分共享参数训练与新用户是否再更新参数。
- **新用户显式优化：**[Premier](https://arxiv.org/abs/2603.20725) 为新用户优化已有用户向量的组合系数，因此不能因为生成器冻结就标成“新用户无需优化”。
- **评分与生成阶段不同：**[PIGReward](https://arxiv.org/abs/2511.19458) 的偏好评分可由上下文完成，但其 prompt 优化还涉及训练；[PAMELA](https://arxiv.org/abs/2604.07427) 的评分预测协议与迭代生成搜索也是两套需要分别审查的实验。
- **交互式短期目标：**[PrefGen（相对属性）](https://arxiv.org/abs/2304.00185) 从连续比较定位属性偏好。它与同名多模态论文是不同工作；会话内属性定位不能直接解释为长期跨 prompt 偏好迁移。

以上是方法设定的概括，不提供跨论文速度或效果排名。基座模型、历史长度、候选数和优化预算不同，性能数字通常不能直接横比。

## 真实用户、代理评价与合成偏好

必须把四件事分开：与历史更相似、总体质量更高、换用户条件后结果变化、本人更喜欢按本人条件生成的结果。前面三项均不能单独推出第四项。

**作者报告的证据例子：**[ViPer 的正式论文](https://www.ecva.net/papers/eccv_2024/papers_ECCV/papers/09492.pdf) 包含本人条件与他人条件的用户比较；[PAMELA 项目](https://pamela-bench.github.io/) 说明盲评个性化生成结果的流程。这类设计更直接地针对个体偏好，但仍要查参与者选择、基线质量、提示词覆盖和置信区间。

**不能混写的例子：**[PPD 原文](https://arxiv.org/html/2501.06655) 的生成胜率使用模型裁判，使用真实用户的历史并没有把裁判变成用户本人。[Premier 原文](https://arxiv.org/html/2603.20725) 的专家根据历史图判断匹配程度；这与历史拥有者亲自选择不同。[PIGReward 原文](https://arxiv.org/html/2511.19458) 同时使用人工和自身评分评价，后者有优化与评价依赖的问题。

**评分预测不能冒充生成验证：**[LAPIS](https://arxiv.org/abs/2504.07670) 提供艺术图片的个体评分任务，本仓库将其列为支撑工作。其预测误差不能直接说明生成结果更合本人喜好。反过来，PAMELA 和 PIGReward 有实际生成控制实验，所以没有被归成“只有评分”。

**数据版本要对齐：**[PAMELA 发布数据卡](https://huggingface.co/datasets/bethgelab/PAMELA) 与论文概述存在人数、图片数和评分数的口径差异；仓库同时保留了两种来源，未把四舍五入后的概述当成发布集精确规模。[PIPBench 项目](https://wuyuhang05.github.io/PIPBench/) 区分真实用户与合成 agent，以及图片和 testcase；这些单位不可互换。

**整理判断：**模拟偏好适合控制变量和规模化训练，但其“喜欢”受生成规则与裁判影响；第三方人类评价有真实感知，却不一定知道目标用户的理由。人口学属性、用户文本档案和真实视觉选择应各自报告，避免从群体特征推断某个个体必然喜欢什么。

## 近期补充：2026 年 6—9 月及遗漏补录

本轮核验时间为北京时间 2026-09-17（UTC 2026-09-16），纳入的最新预印本发布于 9 月 11 日。这是选择性更新；完整来源及状态见 [维护记录](updates.md) 和 [JSON](../data/resources.json)。

- **画像驱动生成：**[ZIPP](https://arxiv.org/abs/2606.08841) 把行为历史或问卷转成 persona，再改写生成提示词。它没有新用户参数更新，但画像挖掘仍有共享训练和用户信息输入；不能把“零样本”解释为整条流程不需要用户数据。
- **广告场景的两种证据：**[AdMan](https://arxiv.org/abs/2609.12694) 检查个性化广告流水线的技术可行性；[配套用户研究](https://arxiv.org/abs/2609.12697) 收集接收者本人对不同个性化程度的评价。后者报告中等程度更受欢迎，但购买意愿是自报指标，不能直接解释为真实转化率，也不能推出个性化越强越好。
- **生成与修图：**[DPPMG](https://arxiv.org/abs/2604.20434) 用离散偏好 token 生成图文，评测采用按时间划分的交互记录；这不等于未见用户实验。[C-DPO](https://arxiv.org/abs/2511.05616) 学习个性化编辑提示策略，要分开读合成用户、第三方评审和附录的小规模本人偏好实验。[FedPAIE](https://arxiv.org/abs/2607.27659) 用个人评分器指导调色，确实改变图像，但生成提升主要以该评分器的分数衡量。
- **评分支撑：**[PALATE](https://arxiv.org/abs/2608.18622) 选择已有专家修图候选；[PRAC](https://arxiv.org/abs/2607.15752) 选择信息量较大的样本并合并相近用户模型；[XPASS-Vis](https://arxiv.org/abs/2606.15629) 支持跨领域审美评分。这三者不能仅凭评分实验被解释为已经验证了个性化图像生成。

PRAC 和 PALATE 接入新用户仍需参数优化。XPASS-Vis 虽有用户级交叉验证，也用目标用户的评分做适配；“测试用户未出现在共享训练中”和“新用户零样本”是两件事。

## 初学者的可选阅读路线

先用 [Tailored Visions](https://arxiv.org/abs/2310.08129) 理解历史信号如何参与生成，再用 [ViPer](https://arxiv.org/abs/2407.17365) 对照带理由的反馈与用户实验。随后读 [PPD](https://arxiv.org/abs/2501.06655) 和 [Premier](https://arxiv.org/abs/2603.20725)，比较新用户直接条件化与参数优化。最后把 [PIPBench](https://arxiv.org/abs/2607.06440)、[PAMELA](https://arxiv.org/abs/2604.07427) 与 [PIGReward](https://arxiv.org/abs/2511.19458) 放在一起审查评测闭环。这是教学顺序，不是历史优先权或权威排名。

每篇论文写一张简短阅读卡：输入历史的含义、共享训练数据、用户/内容划分、新用户更新参数、测试基座、评价者身份、生成与评分分别支持什么结论。未确认的内容写“未核实”，不要从标题补全。

## 待验证问题

以下是从任务结构归纳的问题。开展选题前仍需继续查新，不能据此宣称某一方向无人研究。

- **可辨识性与内容混杂：**仅观察喜欢图，怎样区分喜欢某种风格、喜欢主体，还是只看到了这一类图？配对反事实、解释反馈或主动询问能增加什么可识别信息？
- **多模态与情境偏好：**一个人可同时喜欢几种不相容的风格。当前目的、题材和使用情境如何决定激活哪一种，而不是平均成一个向量？
- **少样本泛化：**未见用户、未见 prompt、未见主体和未见模型是不同泛化轴。固定历史预算时应如何选择有信息量的样本？
- **偏好漂移：**短期任务偏好与长期审美如何区分？更新过程中怎样保留旧偏好的适用情境，怎样允许用户撤销错误推断？
- **隐私：**历史图片、评分和用户表示可能携带私人内容。能否减少历史保留量，在可审计的同意与删除机制下完成适配？
- **评价成本：**怎样用少量目标用户判断校准代理评价，并报告跨用户差异、统计不确定性和退出/缺失数据？什么时候适合主动追加真人评价？

讨论这些问题时，同时保留任务满足度、一般画质与个体满意度三个维度；不要用单一代理分数代替完整结论。新增文献按 [贡献流程](../CONTRIBUTING.md) 核验，尚未完成身份或证据核查的线索进入 [backlog](search-backlog.md)。
